# 命令：PRD 问答

基于 PRD 及 context 知识库，回答关于需求的具体问题：

$ARGUMENTS

## 使用说明

任何人（产品、研发、测试、设计）都可以用此命令提问，也可以用自然语言触发：

**直接命令触发：**
- `/prd-qa 用户登录模块的 Session 超时时间是多少？`
- `/prd-qa F-001 的验收标准第二条具体是什么？`
- `/prd-qa 这个功能的字段清单在哪里？`

**自然语言触发（无需输入命令）：**
- "我想问几个产品问题"
- "PRD 里这个功能的权限规则是怎么说的？"
- "这个功能的边界条件是什么？"

**不适用场景（以下问题不在知识库范围内，不触发此命令）：**
- 代码解释、技术实现方案、Bug 原因分析（含"这段代码"/"报错"/"怎么实现"）
- 竞品分析、市场调研、用户调研
- PRD 内容修改请求（含"帮我改"/"优化一下"/"新增一个"等改写意图）
- 与产品文档无关的通用问题

## 执行步骤

**0. 入口行为（KQA-RTG-001）**

`$ARGUMENTS` 为空，或用户以自然语言表达"想问产品/PRD 相关问题"但未说出具体问题时：

- 输出引导语：「我会基于产品上下文和 PRD 帮你检索，请说出你的问题。」
- 等待用户输入具体问题后，再进入步骤 1
- **不**提前触发问题清晰度收敛流程；等用户说出问题后再判断

**1. 问题收敛（KQA-QRY-004 / KQA-QRY-005）**

用户输入具体问题后，执行以下两项检查：

**1a. 清晰度判断**

判断问题是否含有可检索锚点（功能名、PRD ID、字段名、明确的业务对象）：

- **含锚点（清晰）**：直接进入步骤 2
- **无锚点（模糊）**：输出一句话追问，等待用户补充，最多追问 3 次：
  - 3 次内用户补充了锚点 → 进入步骤 2
  - 达到 3 次上限仍无锚点 → 以现有信息进入步骤 2，回答时标注「基于有限信息检索，结果可能不精确」
  - 用户说「直接找」/「就这样」等中止信号 → 停止追问，进入步骤 2

**1b. 多意图检测**

若问题中含有 2 个或以上独立意图（如「登录的超时规则和权限怎么配」）：

- 识别并拆分为有序意图列表，在回答开头说明「检测到 N 个问题，逐一回答」
- 按序对每个意图执行步骤 2-4，分块输出（每块含子问题标题 + 回答 + 来源标注）
- 单次最多处理 3 个意图；超出时回答前 3 个，提示「本次回答前 3 个问题，其余请分次提问」

**2. 意图识别（KQA-QRY-001）**

分析问题关键词，识别问题领域：

| 领域 | 信号关键词 | 优先检索层 |
|------|-----------|-----------|
| 产品背景类 | "是什么"/"定位"/"背景"/"有哪些功能" | context/ 优先 |
| 功能规则类 | "规则"/"逻辑"/"流程"/"怎么处理" | context/ 优先，未命中进入 PRD 层 |
| 字段定义类 | "字段"/"参数"/"类型"/"长度"/"格式" | context/ 优先，未命中进入 PRD 层 |
| 边界条件类 | "边界"/"异常"/"如果…怎么"/"失败时" | context/ 优先，未命中进入 PRD 层 |
| 权限规则类 | "权限"/"角色"/"谁能"/"谁看" | context/ 优先，未命中进入 PRD 层 |

**意图处理规则**：
- **意图明确**：静默确认领域，直接进入分层检索（不向用户展示中间步骤）
- **意图模糊**（无法判断具体功能或领域，且步骤 1 追问已完成）：输出一句话确认——「您是在问[方向A]还是[方向B]？」，等待用户回复后再检索
- **纯闲聊**（不含任何产品相关关键词）：提示「这个问题超出了 PRD 知识库的范围，请提问与产品需求相关的问题」，不进入检索
- **未指定目标 PRD**：询问「请问是关于哪个功能的问题？」，不随意选择一个 PRD 回答
- **多领域问题**：按优先级先检索主领域，未命中再检索次领域

**3. 分层定向检索（KQA-QRY-002）**

按以下四层优先级顺序逐层检索，**命中即停，不继续向下**：

**第一层：context/**

根据问题领域读取对应 context 文件：
- 产品背景 → `context/product-background.md`
- 权限规则 → `context/permission-model.md`
- 业务术语 → `context/business-glossary.md`
- 用户角色 → `context/user-persona.md`
- 产品策略 → `context/product-strategy.md`
- 功能结构 → `context/product-feature-map.md`

命中 → 输出答案 + 来源标注（见步骤 4），停止检索。

**第二层：正式区 PRD 索引**

读取 `prds/_registry.md`，根据问题中的 PRD ID 或功能名称关键词定位相关 PRD：
- 包含 PRD ID（如 F-001）→ 按 ID 匹配
- 包含功能名称关键词 → 按标题匹配
- 未找到相关 PRD → 跳过第三层，进入第四层

**第三层：具体 prd.md**

读取第二层定位的 PRD（路径来自 registry），如有 `fields.md` 一并读取。精确查找问题相关章节。

- 只读 `prd.md` 当前版本，不读 `archive/` 下的历史文件
- 每次检索最多读取 3 份 PRD；超出时提示「相关 PRD 较多，已检索前 3 份，如未命中请指定具体 PRD 标题重新提问」
- **章节存在但内容为空**：先向用户追问（「该章节存在但内容未填写，是否有更具体的问法？」）；若仍无法回答，走兜底流程（步骤 5）

命中 → 输出答案 + 来源标注，停止检索。

**第四层：草稿区 drafts/**

检索 `drafts/` 目录下相关标题的 `prd.md` 或 `rdd.md`。

- 命中 → 输出答案 + **⚠️ 草稿警告标注**（见步骤 4）
- 未命中 → 触发兜底回复（见步骤 5）

**4. 答案生成与来源标注（KQA-ANS-001 / KQA-ANS-002）**

**回答规则**：
- 基于原文生成自然语言回答，**不添加推断内容**
- 直接给出答案，不大段复述 PRD 原文
- 引用原文不超过 300 字，超出时摘取最相关段落，标注「以下为节选」
- 引用原文时使用引号

**来源标注（强制项，有命中必须标注，不可省略）**：

正式区 PRD 来源：
```
> 来源：prds/[标题]/prd.md §[章节编号] [章节名]
```

context 来源：
```
> 来源：context/[文件名].md
```

草稿区来源：
```
> ⚠️ 来源：drafts/[标题]/prd.md（草稿文档，未正式发布）
```

**特殊场景**：
- **命中章节内容为空/占位符**：已在步骤 3 追问处理；若走到此步仍无内容，输出「该章节在 PRD 中存在但内容未填写，建议通过 `/update-prd` 补充」
- **多个 PRD 对同一概念有不同定义**：提示「发现多处相关定义，请确认以哪个 PRD 为准」，列出冲突的两处原文及各自来源
- **PRD 内容存在歧义**：输出原文，标注「此处表达可能存在歧义，建议 PM 通过 `/update-prd` 补充澄清」

**5. 兜底回复与补充引导（KQA-QRY-003）**

四层检索均未命中时，按以下格式输出：

**标准兜底声明**（不做任何推断）：
```
当前文档中暂无关于「[问题关键词]」的记录。
```

**补充建议**（根据问题类型选择最相关的一条）：
- 有相关 PRD 但章节缺失 → 「建议通过 `/update-prd [标题]` 补充相关内容」
- 连相关 PRD 都不存在 → 「建议先通过 `/requirement-clarifier` 澄清需求，再建立 PRD」
- 问题属于产品背景/策略层面 → 「建议在 `context/product-background.md` 或 `context/product-strategy.md` 中补充」
- 问题超出 PRD 知识库范围（如竞品分析等）→ 兜底声明后提示「此类信息不在 PRD 知识库范围内」

**6. 缺陷主动提示**

回答问题的同时，如果发现：
- 问到的内容 PRD 中没有定义
- 存在明显的逻辑矛盾
- 某个边界条件没有覆盖

主动提示：「⚠️ 发现潜在缺陷：[描述]，建议运行 `/update-prd` 补充。」

**7. 启发式追问引导（KQA-GDE-001）**

**触发条件**：步骤 4 成功生成了带来源标注的回答（兜底回复时不触发）。

基于命中来源，在回答末尾追加追问建议：

- **关联内容型**（1 条）：取命中章节的同级或相邻章节，推测用户可能感兴趣的问题；范围限定在本次命中的同一 PRD 文档内
- **延伸探索型**（1-2 条）：基于问题关键词，推荐相关联的未被提及的功能或规则；范围限定在本次命中的同一 PRD 文档内

**输出格式**：

```
**你可能还想问：**
1. [完整问句，用户可直接发送触发下一次检索]
2. [完整问句]
3. [完整问句（可选）]
```

**约束**：
- 追问建议不得与本次问题语义重复
- 追问问句须为完整可读句，不使用省略或缩略表达

## 约束

- 本命令**只读**，不修改任何 PRD 或 context 文件
- 答案严格基于文档原文，不做额外推断、解释或延伸
- 草稿区来源必须 100% 标注 ⚠️ 警告，不得作为正式答案呈现
- 有文档命中必须有来源标注，无例外；无来源的内容一律不输出
