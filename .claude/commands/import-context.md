# 命令：导入上下文（Import & Classify）

将以下内容导入到产品上下文文件中：

$ARGUMENTS

## 执行步骤

**1. 内容类型解析（CTX-IMP-001）**

识别 PM 提供的内容格式和业务含义：

**格式识别**：
- 纯文字 → 继续
- Markdown 文件 → 继续
- PNG/JPG 截图 → 走截图库流程（步骤 4）
- 不支持的格式（PDF/Figma/Word/Excel）→ 拒绝：「当前支持文字、.md 文件、图片截图，[格式] 暂不支持」，停止执行

**语义解析**：判断内容属于哪类业务信息：

| 业务含义 | 归属文件 |
|---------|---------|
| 产品背景/定位 | context/product-background.md |
| 产品策略/原则 | context/product-strategy.md |
| 用户角色/画像 | context/user-persona.md |
| 业务术语 | context/business-glossary.md |
| 功能模块信息 | context/product-feature-map.md |
| 权限规则 | context/permission-model.md |
| 页面截图 | context/screenshots/[模块]/ |

**语义模糊时**：追问 1 个区分问题（如「这段内容主要描述的是产品背景、用户信息、还是功能规则？」），不强行分类。

**内容与现有文件有重叠时**：标注重叠部分，询问是补充还是替换。

**2. 分类建议生成（CTX-IMP-002）**

生成分类建议表，批量展示：

> | # | 内容摘要 | 建议归类文件 | 建议写入位置 |
> |---|---------|------------|------------|
> | 1 | [摘要] | [文件名] | [章节/字段] |

内容涉及多个 context 文件时，拆分为多条建议行。

无合适归属文件时，标注「暂无合适归类，建议 PM 指定或新建上下文文件」。

展示后输出：
> 以上分类建议，回复「确认」批量写入，或指出需要修改的条目，或回复「取消」放弃导入。

等待 PM 确认（**阻塞**）。

**3. PM 确认写入（CTX-IMP-003）**

根据 PM 回复：

- **「确认」**→ 批量写入所有建议条目：
  - 追加方式写入目标文件对应章节，不覆盖已有内容
  - 写入前检查重复：相同信息已存在时提示跳过
  - 写入完成后输出摘要：「已写入 N 条内容：[目标文件列表]」

- **指出修改** → 更新该条分类，重新展示完整建议表，再次等待确认

- **「取消」**→ 不写入任何内容，结束流程

**目标文件不存在时**：询问 PM 是否创建该文件，确认后创建并写入。

**强制规则**：AI 不得在未获得 PM 确认的情况下写入任何 context 文件。

**4. 截图库流程（CTX-IMP-004 ~ CTX-IMP-008 + CTX-NAV-001 ~ CTX-NAV-003）**

仅当内容为截图时执行。

**4a. 前置引导（CTX-IMP-004）**

在收集任何模块信息之前，先输出一行建议提示：

> 建议先将截图整理至 `assets/[功能名]/` 目录，再进行导入，便于后续追溯。

提示为建议性，PM 可直接粘贴截图继续，不强制阻断。

**4b. 模块归类与截图存放（原 CTX-SCR-001）**

1. AI 解析截图内容，识别所属功能模块
2. 若无法自动识别：询问 PM「这个截图属于哪个功能模块？」
3. PM 确认模块后，AI 建议文件名（格式：[页面名称].png）
4. 写入 `context/screenshots/[功能模块]/[页面名].png`
5. 模块目录不存在时自动创建
6. 文件名重复时询问是否覆盖，或建议追加日期后缀

同时记录截图是否来源于 `assets/` 目录（供步骤 4g 使用）。

**4c. 父页面收集——展示已有节点列表（CTX-IMP-005）**

1. 读取 `context/page-navigation.md`（全局索引）和对应模块 `context/screenshots/[模块]/navigation.md`（若存在），提取所有已有节点名称
2. **有节点时**：以编号列表展示（格式：`N. 节点名（所属模块）`），末尾追加 `Other（自行输入）`，等待 PM 选择
3. **无节点时（首张截图，导航图未初始化）**：输出「当前导航图尚未初始化，请描述该页面的入口（如：首页/直接访问/应用启动后进入）」，接受自由文本作为根锚点

**4d. 触发方式收集（CTX-IMP-006）**

PM 选定父页面后，询问：

> 从 [父页面名] 进入此页面的触发方式是什么？（如：点击某按钮/菜单项/链接）

PM 自由文本输入；若 PM 回复「不确定」「跳过」等，将触发方式记录为「待补充」，连边标注「触发方式待补充」，继续写入不阻断。

**4e. 父节点缺失处理（CTX-IMP-007）**

当 PM 通过 Other 输入的父页面名在所有 `navigation.md` 和全局索引中均不存在时：

1. 输出阻断提示：「父页面 [X] 尚未在导航图中，建议先导入父页面截图以保证导航图的连通性。继续导入当前截图，还是先去导入父页面？」
2. **PM 选择先导入父页面**：暂停当前流程，引导 PM 重新开始导入父页面截图
3. **PM 坚持跳过**：在对应模块 `navigation.md` 中创建占位节点 `[父页面名\n待补充截图]`，建立连边，继续写入；输出末尾追加：「占位节点 [X] 已创建，标注「待补充截图」，建议后续补录」
4. 同一对话中同一占位节点被再次引用时，直接复用已有占位节点，不重复创建提醒

**4f. 写入导航图——模块详情文件（CTX-NAV-002 + CTX-NAV-003）**

1. 检查 `context/screenshots/[模块]/navigation.md` 是否存在：
   - **不存在**：创建文件，写入标准文件头（`> 维护规则` 说明）+ 空 Mermaid 图块（`graph TD`）+ 截图索引表头（`| 截图路径 | 页面描述 | 跳转来源 | 触发方式 |`）
2. 在 Mermaid 图块中追加：
   - **完整页面（独立 URL / 全屏页面）**：方形节点 `节点ID[页面名\n截图文件名.png]`
   - **弹窗 / 抽屉 / 面板（叠加层）**：圆角节点 `节点ID([页面名\n截图文件名.png])`
   - 节点 ID 使用英文短横线格式（如 `launch-step1`），不含空格和中文
   - 若无法判断类型，询问 PM：「这是一个独立页面还是叠加弹窗/抽屉？」
   - 追加父节点到此节点的连边：`父节点ID -->|触发方式| 当前节点ID`
3. 在截图索引表追加一行：`| context/screenshots/[模块]/[截图名].png | [页面描述] | [父页面名] | [触发方式] |`
4. **同名节点已存在时**：提示「节点 [X] 已存在，是更新现有节点（替换截图路径）还是新增别名节点？」等待 PM 确认

**4g. 更新全局导航索引（CTX-NAV-001）**

判断是否为该模块首个出现在全局索引的入口页：
- **是**：在 `context/page-navigation.md` 中追加：锚点节点 → 模块入口页的连边（含触发方式标注）
  - 全局索引不存在时：自动创建文件，写入基础 `graph TD` 块和首个锚点节点，再追加模块入口连边
  - 写入后检查行数，超过 50 行时输出警告：「全局导航索引已超过 50 行（当前 [N] 行），建议检查是否有冗余内容」（不阻断写入）
- **否**：不更新全局索引，仅写入模块文件

**4h. 输出写入预览，等待确认**

将模块 `navigation.md` 新增片段（Mermaid 节点 + 连边 + 索引行）和全局索引变更（若有）合并输出预览：

> 以下内容将写入 [模块]/navigation.md，确认写入？
> ```
> [新增 Mermaid 片段]
> ```
> 新增索引行：`| [路径] | [描述] | [来源] | [触发] |`
> （若有）全局索引追加：`[锚点] -->|[触发]| [模块入口]`

等待 PM 确认（**阻塞**）；确认后执行写入。

**4i. 写入完成后清理询问（CTX-IMP-008）**

写入确认完成后，判断本次截图是否来源于 `assets/` 目录（步骤 4b 已记录）：

- **来源于 assets/**：询问「截图已写入导航图。是否删除 `assets/[功能名]/[截图文件名]` 中的原始文件？」
  - PM 确认删除 → 删除对应 `assets/` 路径下的截图文件，输出「已删除 [路径]」；`context/screenshots/` 中文件不受影响
  - PM 选择保留 → 静默结束，不做任何操作
  - 文件不存在 → 提示「未找到 assets/[路径]，可能已被手动删除」，静默结束
  - PM 要求删除整个目录 → 列出该目录下所有文件，二次确认后批量删除
- **直接粘贴截图（非 assets 来源）**：跳过本步骤，不询问
